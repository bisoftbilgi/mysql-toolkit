# MySQL Logger & Audit Toolkit

**Bisoft - Enterprise Database Monitoring & Audit Service**
This project is a low-resource (Rust-based) and Dockerized service that captures all connection (Connect/Quit) and data (Query/Table Access) events on MySQL in real-time, parses them, and routes them to a centralized PostgreSQL database.

---

## 1. Architecture & Workflow

The system reads raw JSON logs generated by MySQL in real-time and splits them into two different PostgreSQL tables based on the event type:
* **`connection_logs`:** Tracks who connected or disconnected, when, and from which IP.
* **`audit_logs`:** Tracks which SQL commands were executed on which database.

```text
[ MySQL 8.0 (Percona Audit) ] ---> [ /var/log/mysql/audit.log ]
                                            |
[ Docker: mysql_logger (Rust) ] <---(Real-time File Stream)
                                            |
[ PostgreSQL 15/16 ] <--- (Parsed & Routed Records)
2. System Requirements
Operating System: Ubuntu / Debian / RHEL based Linux distributions.

Hardware: Minimum 2GB RAM (Build optimizations are included).

Dependencies: Docker, Docker Compose, Git.

Source: MySQL 8.0 (Percona Audit Log Plugin must be active).

Destination: PostgreSQL 15 or 16.

3. Pre-Installation Preparation (MySQL & PostgreSQL)
3.1. MySQL Percona Configuration
To generate logs in JSON format, the following parameters must be added to your my.cnf (or audit_log.cnf) file, and MySQL must be restarted:

Ini, TOML
[mysqld]
audit_log_format=JSON
audit_log_handler=FILE
audit_log_policy=ALL
audit_log_rotate_on_size=100M
audit_log_rotations=5
3.2. PostgreSQL Database
A PostgreSQL database must be ready to receive the logs (e.g., postgres db). The tables (connection_logs and audit_logs) will be automatically created by the service upon the first run.

4. Installation & Usage Instructions
4.1. Installing Dependencies
If Docker and Git are not installed on the server, complete the installation with the following commands:

Bash
sudo apt update
sudo apt install docker.io docker-compose git nano -y
sudo systemctl enable docker
sudo systemctl start docker
4.2. Cloning the Repository
Pull the project to your server and navigate to the directory:

Bash
git clone <MYSQL-TOOLKIT-REPO-LINK>
cd mysql-toolkit/mysql_logger
4.3. Configuring Environment Variables (.env)
Create a .env file to configure connection settings:

Bash
nano .env
Paste your system-specific information inside and save the file (CTRL+O, Enter, CTRL+X):

Kod snippet'i
DATABASE_URL=postgres://username:password@ip_address:5433/postgres
LOG_PATH=/var/log/mysql/audit.log
4.4. Building and Running the Service
Start the system.
(Note: To prevent OOM (Out of Memory) kills on servers with a 2GB RAM limit, the Rust compiler is optimized in the Dockerfile with the cargo build --release --jobs 1 parameter.)

Bash
sudo docker-compose up -d --build
Initialization: Once completed, the service will start running silently in the background.

Log Check: To verify a successful installation, check the logs: sudo docker logs -f mysql_logger_service

5. Example Scenario & Validation
To verify the system is working properly, follow these steps:

Action: Log in to MySQL with any user and create a table.

Expected Result (Connection): The user's login (Connect) time, IP address, and username are instantly reflected in the connection_logs table in PostgreSQL.

Expected Result (Query): The executed CREATE TABLE command, along with the database name, is saved in the audit_logs table in PostgreSQL.

6. MongoDB Integration (Optional)
For future expansions, the system has the infrastructure to support MongoDB Slow Query logs. If you wish to prepare the MongoDB side:
Set the following parameters to route all operations in JSON format to /var/log/mongodb/mongod.log:

operationProfiling.mode: slowOp

slowOpThresholdMs: 0

7. Troubleshooting
Permission Denied Error: Ensure the Docker user has read permissions for the /var/log/mysql/ directory.

Tables Not Created: Verify the accuracy of the DATABASE_URL in the .env file and ensure the database port is accessible from inside the Docker container.
